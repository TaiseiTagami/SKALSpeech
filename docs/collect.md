# collect — version 2 recording layout

Collect one source WAV and its matching position TXT per speaker per invocation:

```text
tests/local/control/CMF21/
  corpus.yaml
  info.txt
  recordings/
    rainbow/
      speech.wav
      sensors.txt
      recording.yaml
      annotations/   # generated by pipelines
      processed/     # generated by process-csv
    silent_reference/
      speech.wav
      sensors.txt
      recording.yaml
```

```powershell
skalspeech collect CMF21 -c collect_control.yaml --recording-id rainbow
skalspeech collect CMF21 -c collect_control.yaml --identifier 0001 --recording-id silent_reference --recording-type reference
```

The `collect` config supplies `root` (original speaker folder parent),
`audio_subdir`, `identifier` (substring of WAV filename), `output`
(destination speaker parent), `group`, `frequency`, and `folders`.
The source TXT must have the same stem as the WAV. New recordings always use
`speech.wav` and `sensors.txt`; `wav_name` and `pos_name` are legacy
config keys. No automatic discovery or silence classification is performed.

| Option | Behavior |
| --- | --- |
| `-c, --config` | Required collection YAML. |
| `-i, --identifier` | Override WAV filename substring. |
| `-o, --output` | Override collected speaker parent. |
| `--recording-id` | Folder ID (defaults to identifier). |
| `--recording-type` | `speech` (default) or `reference`. |
| `--yaml-only` | Write metadata for existing v2 recording; no WAV/TXT copies or info.txt rewrite. |
| `--column-template` | Reference shared YAML column mappings in speaker corpus.yaml. |

`corpus.yaml` contains speaker/group/frequency, source provenance, column
template, sensor mapping and recording registry. Each `recording.yaml`
contains recording ID, type, task, source paths and optional overrides.
Existing speaker mappings and recording registry entries are retained when
collecting additional recordings.

```yaml
schema_version: 2
subject: CMF21
group: Control
corpus:
  frequency: 250
recordings:
  - id: rainbow
    type: speech
  - id: silent_reference
    type: reference
columns:
  Ch1_X: tongue_tip_x
```

## Metadata-only mode

```powershell
skalspeech collect CMF21 -c collect_control.yaml --yaml-only --recording-id rainbow
skalspeech collect CMF21 -c collect_control.yaml --yaml-only --column-template templates/ema.yaml
```

This requires existing `recordings/<id>/speech.wav` and `sensors.txt`.
It does **not** migrate old `input/` folders; use the
[migration script](recordings.md) first. If the original source is unavailable,
`info.txt` may supply the original WAV path.
See [pipeline](pipeline.md) for inherited columns.
